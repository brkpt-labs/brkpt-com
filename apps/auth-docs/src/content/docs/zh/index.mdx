## 工作原理

brkpt-auth 把稳定的身份验证逻辑和项目特定的实现细节分离开。身份验证能力被组织为一个个独立功能，适配器负责把这些功能接入你自己的应用。

{/* <!-- TODO: 功能注册 / 架构流程图 --> */}

每个功能都会被添加到项目中，通过适配器完成连接，并通过 `BrkptAuthModule` 注册。无论你启用的是 credentials、OAuth、session、blacklist 还是其他任何能力，集成方式都是一样的。

功能之间通过事件而非直接依赖来通信，这样新增能力时不需要改动已有功能。没有添加的功能不会出现在 `BrkptAuthModule` 中。

端口和适配器把基础设施隔离在身份验证核心之外。你的数据库 schema、用户模型、密码策略、JWT 载荷、验证规则和外部服务始终由你掌控。迁移到另一个项目时，通常只需替换适配器，而不用重写身份验证逻辑。

会话管理构建在无状态 JWT 之上，而不是取代它。session 管理、令牌撤销这类有状态能力可以逐步添加，不需要改动核心身份验证流程。

**brkpt-cli** 通过把源代码直接安装进你的项目、并将新功能接入同一套架构，帮你完成这套结构的搭建。

## 集成起来难吗

每个功能都遵循同一套集成流程：添加功能、实现适配器、完成注册。

<Steps>

1. ### 添加功能

   用 **brkpt-cli** 把功能源代码添加到项目中。

   ```bash title="添加 credentials 功能"
   brkpt auth add credentials
   ```

2. ### 实现适配器

   把功能端口接入你现有的应用代码。多数适配器方法只是简单的字段映射，或对某个服务的直接调用。

   ```typescript "CredentialsAdapter"
   // credentials.adapter.ts
   @Injectable()
   export class CredentialsAdapter implements CredentialsPort<User> {
     constructor(private readonly prisma: PrismaService) {}

     findUserByDto(dto: SignInDto | SignUpDto): Promise<User | null> {
       return this.prisma.user.findUnique({ where: { email: dto.email } });
     }

     validatePassword(user: User, dto: SignInDto): Promise<boolean> {
       return bcrypt.compare(dto.password, user.password);
     }

     async createUser(dto: SignUpDto): Promise<User> {
       const password = await bcrypt.hash(dto.password, 10);
       return this.prisma.user.create({
         data: { email: dto.email, password },
       });
     }

     extractUserIdFromUser(user: User): number {
       return user.id;
     }
   }
   ```

3. ### 注册功能

   **brkpt-cli** 会帮你更新 `features.ts`。实现适配器后，在生成的功能列表中把它传给对应的功能。

   ```typescript ins="CredentialsAdapter"
   // src/brkpt-auth/features.ts
   export const features: FeatureConfig[] = [
     coreFeature(CoreAdapter),
     credentialsFeature(CredentialsAdapter),
   ];
   ```

</Steps>

就这样。`BrkptAuthModule` 在你的 `AppModule` 中注册后，添加的功能就成了同一套 NestJS 身份验证流程的一部分。

根据功能不同，你可能还需要做一些常规的项目配置，比如安装依赖、设置环境变量、定义 DTO 或配置基础设施模块。

</ContainerSection>
